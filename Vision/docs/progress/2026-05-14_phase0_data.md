## 경로 2: NEU Surface Defect (Figshare 미러)

Figshare에 동일 데이터 공개 미러가 있음. API로 직접 URL 확보 → 다운로드.

```bash
# Figshare API로 다운로드 URL 조회
curl https://api.figshare.com/v2/articles/28903550
# → NEU-CLS.zip, 27,316,154 bytes, https://ndownloader.figshare.com/files/54094775
```

```python
import urllib.request, os
os.makedirs('data/raw/neu', exist_ok=True)
urllib.request.urlretrieve(
    'https://ndownloader.figshare.com/files/54094775',
    'data/raw/neu/NEU-CLS.zip'
)
```

**구조** (압축 해제 후):
```
data/raw/neu/
├── train/train/{images,labels}/   # 1770 jpg + 1770 yolo bbox txt
└── valid/valid/{images,labels}/   # 30 jpg + 30 txt
```

- 총 1800장 (6 클래스 × 300장) — NEU 표준 분포 일치
- 200×200 RGB
- 클래스: `crazing`, `inclusion`, `patches`, `pitted_surface`, `rolled-in_scale`, `scratches`
- 원본은 train/valid를 1770/30으로 나눠 놓았는데 **valid가 너무 작음 → 자체 80/20 재분할**

## 데이터 재구성 — YOLO-cls 포맷

YOLO `classify` 모드는 다음 구조를 요구:
```
<root>/
├── train/<class>/*.jpg
└── val/<class>/*.jpg
```

### NEU 재구성 (`data/processed/neu_cls/`)

train(1770) + valid(30) 풀에서 클래스별 80/20 split (`random.seed(42)`).

```
neu_cls/train/<class>/   240 images each  (총 1440)
neu_cls/val/<class>/      60 images each  (총 360)
```

### Casting 재구성

원본 train/test 분할을 그대로 사용 (test가 충분히 크고 클래스별 균형 양호):
```
casting_cls/train/{def_front,ok_front}/    3758 + 2875
casting_cls/val/{def_front,ok_front}/       453 + 262
```
(5/15 학습 직전 스크립트로 자동 생성)
