# 01. 프로젝트 이해 — 무엇을, 왜 만드는가

## 한 줄 요약

> **"사람이 입력하는 것이 하나도 없는 품질 관리 시스템"** — 카메라가 보고, AI가 판정하고, 자동으로 기록하고, 원인까지 추적한다.

## 문제 의식

중소 제조 현장의 품질 관리는 여전히 **사람 눈 + 수기 기록**에 의존한다. 이 구조에서는 세 가지가 동시에 무너진다:

1. **데이터가 안 쌓인다** — 작업자가 바쁘면 기록을 건너뛰고 시간도 대충 적는다. "오늘 몇 시에 불량이 급증했나?" 에 답할 수 없다.
2. **원인을 모른다** — 불량 시점의 공정 조건(온도/압력/속도)과 기록이 연결되지 않으니, 같은 불량이 매주 반복돼도 분석이 불가능하다.
3. **AI 도입을 못 한다** — 중소 제조기업 80%가 AI 필요성을 느끼지만, AI 비전 도입의 77%가 파일럿 단계에서 멈춘다 (ABI Research 2026). 이유는 산업용 카메라/조명/GPU 서버 같은 **초기 투자 비용**.

## 솔루션 — PunchLine

**파이프라인 (전체 풀체인)**

```
[카메라 이미지]
   ↓ ───────────────────────────────┐
   │                                │ Vision Engine (정환)
   │   ① YOLO v8n — 양품/불량 + 유형 분류
   │   ② PatchCore — 양품 학습 기반 이상 탐지
   │   ③ FastAPI /inspect — JSON 결과 반환
   ↓
[판정 결과 + 타임스탬프]
   ↓ ───────────────────────────────┐
   │                                │ Data Intelligence (지민)
   │   ④ 공정 센서 데이터와 시간 조인
   │   ⑤ SHAP 기반 원인 변수 Top3
   │   ⑥ 조치 가이드 매칭
   ↓
[Streamlit 대시보드 — 검사 화면 + 시계열 + 원인 + 가이드]
```

**핵심 차별화**
- 기존 솔루션은 "분석 도구"를 판다 → 현장에는 분석할 데이터가 없다.
- PunchLine은 **"데이터 생성 엔진"** — 데이터가 알아서 쌓이게 만든다.
- "상관관계"가 아닌 **"인과관계"** — 단변수 상관이 아니라 다변수 SHAP으로 진짜 원인 변수를 특정한다.

## 사용자 시나리오 (대표)

**09:42 — 크랙 불량 3건/10분 감지**
- AI 알림: "A라인 09:42부터 크랙 급증"
- 자동 매칭: "금형 온도 86°C — 정상 범위(70~80°C) 초과"
- 인과 분석: "온도+압력 복합 효과 — 크랙 기여도 73%"

**09:44 — 작업자 금형 온도 조정**

**09:55 — 불량률 정상 복귀**
- 전체 과정 자동 기록 → 감사 자료가 0초에 만들어진다.

**기존 vs PunchLine 차이**: 감지 → 원인 → 조치까지 **2분**.

## 평가 비중 (정환이 무엇에 시간을 더 써야 하는가)

| 항목 | 비중 | 정환 책임 |
|------|------|-----------|
| 시연 완성도 | 35점 | **★ 직접** — 검사 화면, Docker 1발 빌드, 시연 시퀀스 |
| AI 정확도 (불량 판정/유형 분류) | 25점 | **★ 직접** — YOLO mAP, PatchCore AUROC |
| 원인 추적 (인과 분석) | 20점 | 간접 — 정확한 타임스탬프 + 결함 유형 제공으로 지민이 분석 가능하게 |
| 조치 가이드 | 10점 | 간접 — 결함 유형 라벨이 지민의 RAG 키로 사용됨 |
| 발표/스토리 | 10점 | 공통 |

→ **정환은 시연 임팩트(35) + AI 정확도(25) = 60점에 직접 영향**. 여기서 80% 이상 가져가는 게 목표.

## 기술 선택 근거 (왜 이 모델/스택을 쓰는가)

| 선택 | 이유 |
|------|------|
| **YOLO v8n** (nano) | 8GB VRAM 환경에서도 학습 가능, 추론 50+ FPS — 시연 시 실시간성 확보. 정확도 손해는 데이터 양으로 메움. |
| **PatchCore** | 양품 이미지만으로 학습 가능 → "도면 없어도 됨" 스토리의 핵심. MVTec AD에서 SOTA. |
| **FastAPI** | 추론을 Streamlit에서 직접 호출하면 UI가 블로킹됨 → API 분리해서 비동기 호출. 지민의 모듈도 같은 패턴으로 붙이기 쉬움. |
| **Docker Compose** | 본선 당일 네트워크 불안 가능성 → 사전 빌드된 이미지로 1발 실행. "현장 도입 가능"의 증거. |
| **Streamlit** | 데모 UI 빠르게 만들기 + Plotly 차트 즉시 사용 가능. 본선용 도구. |
